## PART 1: CURRENT ARCHITECTURE FOUND

### Data Flow Map (As-Is)

```
┌──────────────────────────────────────────────────────────────────┐
│                      CURRENT STATE (2026-04)                     │
└──────────────────────────────────────────────────────────────────┘

1. COINGECKO (Public Market Layer)
   ├─ Function: syncCoinGeckoMarket.js
   ├─ Source: CoinGecko /coins/markets REST API (public, no auth)
   ├─ Entities: Asset (22 hardcoded coins)
   ├─ Data Synced: current_price, change_1h/24h/7d, volume, market_cap, technical proxies (RSI, EMA, MACD, trend, volatility, support/resistance)
   ├─ Image Source: coin.image from CoinGecko → stored in Asset.image_url
   ├─ Triggered: On-demand (User clicks "Sync Live" on Dashboard/Market)
   ├─ Update Method: Upsert (create new or update existing Asset by symbol)
   ├─ Fallback: None (if sync fails, UI uses stale DB data)
   └─ Timestamp: Asset.last_synced (ISO) + data_source='coingecko'

2. KRAKEN REST API (Account & Execution Layer)
   ├─ Function: syncKrakenAccount.js (JUST FIXED SIGNATURE BUG)
   ├─ Source: https://api.kraken.com/0/private/* (requires API key/secret auth)
   ├─ Entities:
   │  ├─ PortfolioAsset (holdings from balance query)
   │  ├─ ExchangeOrder (open/closed orders for tracking)
   │  └─ TradeApproval (pending trades for manual review)
   ├─ Data Synced: account balances, holdings, current value, PnL (unrealized/realized), allocation %
   ├─ Triggered: On-demand (User clicks "Sync Account" button)
   ├─ Update Method: Upsert (create or merge portfolio assets)
   ├─ Credential Flow: Deno.env.get('KRAKEN_API_KEY/SECRET') → not user-settable in app
   ├─ Fallback: If keys missing, returns 400 (kraken_configured: false)
   └─ Timestamp: PortfolioAsset.last_synced (ISO) + data_source='kraken'

   Function: executeTradeOnKraken.js (JUST FIXED SIGNATURE BUG)
   ├─ Source: https://api.kraken.com/0/private/AddOrder (submit real orders)
   ├─ Safety: Dry-run mode (validation_only=true) → Kraken validates but does NOT submit
   ├─ Auth: Signature verification with corrected nonce inclusion
   ├─ Validation Mode: Can test order parameters without live execution
   └─ Live Mode: Only on explicit validation_only=false (frontend never sends this yet)

3. KRAKEN WEBSOCKET (Live Price Layer)
   ├─ Hook: useKrakenTicker.js
   ├─ Source: wss://ws.kraken.com/v2 (public, no auth needed for ticker)
   ├─ Connection: Auto-connects when component mounts and pairs array is non-empty
   ├─ Subscriptions: Dynamically subscribe to ['BTC/USD', 'ETH/USD', ...] based on visible assets
   ├─ Data: ticker.last, bid, ask, change_pct, volume
   ├─ Memory State: prices object keyed by pair (in-memory, lost on page reload)
   ├─ Fallback: If WS disconnects, UI falls back to Asset.current_price (CoinGecko)
   ├─ Reconnect: Auto-reconnect every 5s on disconnect
   ├─ Used By: Positions page, AssetDetail page
   └─ NOT Used: Dashboard (no live prices), Portfolio (no ticker)

4. LOCAL / MANUAL DATA
   ├─ Position (manual tracking table)
   │  ├─ Entry price, quantity, side (long/short), stop loss, TP levels
   │  ├─ Manual user input (no auto-sync from Kraken)
   │  └─ Real-time price update: Uses Kraken WS via useKrakenTicker
   ├─ PortfolioAsset (hybrid)
   │  ├─ Can be manually added (Portfolio page form)
   │  ├─ Or synced from Kraken REST (Sync Account button)
   │  └─ Manual add does NOT pull from Kraken
   └─ Risk Settings, Trade Approvals, Alerts (all DB-only, no sync)

5. AI & SIGNALS (Logic Layer)
   ├─ AISignal entity (created by agents, stored in DB)
   ├─ TradeApproval entity (manual or AI-generated, human review required)
   ├─ ExchangeOrder entity (order history + status tracking)
   ├─ Source: Generated by backend agents, NOT synced from Kraken
   └─ Note: No real-time webhook from Kraken for fills — uses polling via useKrakenOrderStatus

---

### Current Data Source Boundaries (AS-IS)

| Entity | Source(s) | Auto-Sync | Manual Input | Fallback |
|--------|-----------|-----------|--------------|----------|
| **Asset** | CoinGecko only | Yes (on-demand) | No | Stale DB data |
| **PortfolioAsset** | Kraken REST OR manual form | Optional | Yes | Mixed (manual + Kraken) |
| **Position** | Manual form only | No | Yes | Live WS prices |
| **ExchangeOrder** | Kraken REST (polling) | Every 30s if open | No | Stale DB data |
| **AISignal** | Agents (backend logic) | No | No | N/A |
| **TradeApproval** | Manual creation + agents | No | Yes | N/A |
| **Price display** | WS (live) + Asset.current_price (fallback) | Real-time WS | No | CoinGecko DB |

## PART 2: TARGET ARCHITECTURE PROPOSAL

### Vision: Clean Data Source Separation

```
┌──────────────────────────────────────────────────────────────────┐
│                      TARGET STATE (Post-Refactor)                │
└──────────────────────────────────────────────────────────────────┘

TIER 1: PUBLIC MARKET DATA (CoinGecko)
├─ Purpose: Market overview, metadata, icons, historical prices
├─ Entity: Asset (read-only in UI, synced on-demand)
├─ Controls: Move to Connections > Market Data Sources
├─ UI: Market page shows "Last synced: 5m ago" with one button
└─ Dashboard: Removed explicit sync (pulled on load, cached)

TIER 2: ACCOUNT & PORTFOLIO (Kraken REST)
├─ Purpose: User holdings, balances, order execution, history
├─ Entities: PortfolioAsset, ExchangeOrder, TradeApproval
├─ Controls: Move to Connections > Exchange Accounts
├─ UI: Portfolio page streamlined, Account section in Connections
├─ Status: Shows "Connected", "Last synced: 2m ago", clear error states
└─ Credential Management: Settings > Connections > Add Exchange (explicit form)

TIER 3: LIVE PRICES (Kraken WebSocket)
├─ Purpose: Real-time ticker for positions, asset detail
├─ Memory: Stays client-side (in-memory prices)
├─ UI: Only shown where relevant (Positions, Asset Detail, NOT Dashboard overview)
└─ Status: Compact WS indicator (dot + "Kraken Live")

TIER 4: MANUAL TRACKING (Local DB)
├─ Position tracking (no Kraken auto-sync, user-driven)
├─ Custom alerts, watchlists
├─ Manual trade planning (before Kraken execution)
└─ Stays on dedicated pages (Positions, Alerts, Risk)

TIER 5: AI & LOGIC (Agent-Driven)
├─ Signals, approvals, risk scoring
├─ No new data sources — outputs to DB
└─ Remains agent-driven, manual approval workflow

**Dashboard** (High-level overview only)
├─ Portfolio value card (cached, ~5m old)
├─ Key metrics (open positions, signals, alerts)
├─ PnL chart (historical from PortfolioValueHistory)
├─ NO explicit sync buttons
├─ NO CoinGecko/Kraken status inline
└─ Call-to-action: "View Detailed Data Sources" → Links to Connections

**Connections (NEW PAGE)**
├─ Tab 1: Market Data Sources
│  ├─ CoinGecko status (last sync, sync button, error display)
│  ├─ Rate limit info
│  └─ Data freshness indicator
├─ Tab 2: Exchange Accounts
│  ├─ Kraken status (connected/not configured)
│  ├─ Sync button + last sync timestamp
│  ├─ Account info (balance count, open orders)
│  ├─ Add/edit/remove credentials
│  └─ Test connection button
└─ Tab 3: WebSocket Status (Kraken Live)
   ├─ Connection status
   ├─ Active subscriptions (BTC/USD, ETH/USD, ...)
   └─ Reconnect counter

**Market** (Refined)
├─ Asset list (CoinGecko data)
├─ Single "Refresh" button → triggers syncCoinGeckoMarket
├─ Shows: "Last updated: 5m ago · 22 assets"
└─ Data source badge per row

**Portfolio** (Simplified)
├─ Holdings list (mixed: manual + Kraken-synced)

**Positions** (Unchanged)

├─ Kraken WS status dot (when trading)

**Settings** (Retain)

├─ Authentication (future 2FA, etc.)
